- **0 divergencias de CS pendientes** tras la alineación API Clients (verificado live en Designer TEST + MCP read-only):
  - `SCA2_APIClients_Login` → **CMP Login token** (`_a-0000ea92-10b3-8000-9c1b-011c48011c48_8636336`). Test: HTTP 200, success=true, ~320 ms. Body con `cons!SCA2_TXT_APICLIENTS_*` (sin credenciales literales).
  - `SCA2_APIClients_search`, `SCA2_APIClients_contactMethod`, `SCA2_APIClients_Benefits` → **CMP API Clients** (`_a-0000ea92-10b3-8000-9c1b-011c48011c48_8634288`). Header Authorization en las tres: `"Bearer " & index(rule!SCA2_APIClients_Login(), "result", "body", "access_token", "")` (antes `rule!CMP_APIGW_newToken_TEST()`). Son los mismos CS que usan las integraciones API Clients de SCA (CMP_*) → cumple "poner los sistemas conectados de SCA". Cambios vía Designer UI (MCP TEST read-only, 405 en escrituras).
  - `SCA2_cargaGestionSGC3` **se queda en `SCAC_SGC3`** (`_a-0000f036-fd58-8000-9cc1-011c48011c48_19914595`): SCA no tiene integración SGC3 propia; la ruta runtime de SCA es `SCAC_cargaGestionSGC3 → SCAC_SGC3` (el CS desplegado en TEST para esto). `CMP MapfreDigitalHealth SGC3` lo usan solo `CMP_AltaVencimientos{Auto,Hogar,Comunidades}SGC3` (producto distinto, no equivalente probado). No cambiado.
